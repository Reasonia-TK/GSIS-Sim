## 0. 結論

| 1 | **実行できる** | 1/4 領域(対称面 2 枚)、Δx = R/8、セル内ランダムの衝突相手、入口状態で 16 粒子/セル(約 380 万粒子)、Δt = 0.05 t_ref、8,000 ステップ | 約 20 分(0.12 s/ステップ) |
| 10 | **実行できる** | 1/4 領域、Δx = R/10、仮想サブセル(最近接の衝突相手)、28 粒子/セル(約 1,280 万粒子)、Δt = 0.02 t_ref、18,000 ステップ | 約 2 時間(実測 0.35 s/ステップ) |

| 1000 | できない | δ=100 よりさらに大きい | — |

t_ref = R / sqrt(2 R_g T0)(R = 1 mm で 0.939 µs)。

- 試運転(δ=1、Δx = R/4、3,000 ステップ、2 分 13 秒)は正常に終わり、流入・流出・壁・対称面が意図どおり動いた。無次元質量流量は **Ṁ = 0.190 ± 0.003**(論文の DSMC 値 0.197 に対して −3.5%、約 2σ)。中心線は論文 Fig.3 の GSIS-PBC の線と、差の RMS が p/p_in で 0.021、u_x/sqrt(2RT0) で 0.029(統計誤差の約 2 倍)。粗い格子・短い平均時間の値で、本計算で確かめる必要がある(§6)。
- 初回の試運転は「体積率 0 と判定されたセルに粒子がいる」として停止した。円筒壁が格子点のすぐ近くを通る所に、体積率の中点積分で拾えない微小な流体部分ができるためで、y・z 方向のセル幅を Δx から 0.35〜0.5% ずらして回避した(§2.6)。
- 流入処理は入口面に接するボックスの数に比例して遅くなる。`amr.max_grid_size = 128` で δ=10 の 1 ステップが 0.59 s → 0.35 s になった(§2.7)。
- 主な不足機能は、軸対称計算・可変の粒子重みや格子がないこと(費用の大半が上流槽に使われる)、境界の通過量と線上の値を出力できないこと。後者は plotfile からの後処理で補った(§3)。

## 1. DSMC コードの機能(この検証に関係する部分)

| 項目 | 内容 | 管ケースでの使い方 |
|---|---|---|
| 格子 | AMReX の単一レベル・一様な直交格子(3 次元)。軸ごとにセル幅を変えられる。AMR・局所時間刻み・可変重みはない | 全域で同じ Δx・Δt・Fnum |
| 衝突 | NTC 法、VHS / VSS、Bird (1994) の散乱。分子種の定数は入力で上書きできる | He、VHS |
| 衝突相手 | セル内ランダム / 固定サブセル / 仮想サブセル(最近接、O(N²)/セル) | δ=10 で仮想サブセル |
| 形状 | 閉じた STL(BVH で軌道と交差判定)。`fluid_inside = 1` で内側を流体にできる(1 個まで)。セルの気体体積率は中点則(各軸 `surfaces.volume_samples` 点)で求め、衝突と密度の正規化に使う | 3 つの円筒の和の内部を流体にする |
| 計算領域の境界(6 面) | periodic / symmetry / specular / diffuse / inflow / outflow / emission | 入口 = inflow、出口 = outflow、y=0・z=0 = symmetry |
| 形状の面ごとの境界 | 面 ID の対応ファイルで、STL の面ごとに diffuse / specular / symmetry / outflow / inflow / emission を指定できる | 使わない(端面は領域の面で与える方が検証済みで簡単) |
| inflow | 面に到達した粒子を吸収し、指定の数密度・温度・速度の Maxwell 分布の流束で粒子を入れる(槽の境界) | n_in、T0、速度 0 |
| 出力 | AMReX plotfile(n, rho, u, v, w, T, p, ppc, 衝突頻度, λ, MCS, MCS/λ, 気体体積率)、軸方向の平均プロファイル CSV、チェックポイント、流入粒子数のカウンタ | `sample_reset = 1` でブロック平均を出す |
| サンプリング | `output.sample_start` 以降に毎ステップ累積。`sample_reset = 1` で出力ごとにリセット | ブロック平均から定常判定と誤差評価 |
| GPU | CUDA(Windows ネイティブ版あり)。全処理が GPU。メモリプールは `AMREX_THE_ARENA_INIT_SIZE` から必要に応じて拡張 | 128 MiB から開始 |
| CPU 版 | Windows 版は OpenMP なしの 1 スレッド | 使わない |

検証済みの範囲(HANDOFF.md・docs/ の JSON): 平衡気体の衝突頻度・平均自由行程(理論値と 1% 以内)、クエット流・熱伝導の例題、内部エネルギー緩和、任意形状の粒子追跡・反射・体積率(252 項目)、対称面(464 項目)、流量指定(329 項目)、形状の面ごとの境界(343 項目)、CUDA の memcheck。真空排気モデル A では公表値との差が 10〜26% あったが、評価面の定義の違いなどによるとされ、原因は確定していない。**希薄領域の圧力差による管内流れを、参照解と定量的に比べた検証はまだない**(今回の試運転が最初)。

既知の課題(HANDOFF.md §5 から関係するもの): 衝突カーネルは 1 セル 1 スレッドで、粒子の多いセルが律速になる。仮想サブセルはセルあたり O(N²)。サンプリングは原子的加算。粒子は AoS 形式。流入のたびに粒子タイルを伸ばす。チェックポイントの照合に Fnum は含まれない(再開時は同じ入力を使う必要がある)。

## 2. 管ケースへの当てはめ

### 2.1 形状
`validation/dsmc/tools/tube_geometry.py` で、子午面の折れ線を回転した閉じた三角形メッシュを作る(gmsh は使わず、厳密な多角柱の和として直接作る)。

- 円は正 128 角形で近似し、頂点を θ = 2πk/128 に置く。y=0・z=0 面に対して鏡映対称になるので 1/4 領域に使える(スクリプトで頂点集合の対称性を検査)
- 外接半径を R·1.000201 にして、断面積を円と一致させた(等面積)。管の周長は円より 0.010% 長い
- 入口・出口の蓋は計算領域の外(x = −8.1R、14.1R)に置き、流入・流出は計算領域の面で与える(DSMC 側の真空モデル A と同じ構成)
- 24,064 三角形、閉じた多様体・向きの一致・体積(解析値と 1e−16 の差)を確認。R 単位で書き、入力の `surface0.scale = R[m]` で SI 単位にする
- x = 0 と x = 10R の環状の壁はセル境界に一致させる(微小な切れ端を作らない)

### 2.2 境界
| 面 | DSMC の設定 | 備考 |
|---|---|---|
| 上流槽の端面(x = −8R) | 領域面 `bc.xlo.type = inflow`、n = n_in、T = T0、速度 0 | 槽の円の外側に置かれた候補粒子は捨てられる(全候補の 30.9% = 正方形と円の面積比どおり) |
| 下流槽の端面(x = 14R) | 領域面 `bc.xhi.type = outflow` | 到達した粒子を消す(真空) |
| その他の壁 | STL `surface0.type = diffuse`、T0 | 完全拡散 |
| 対称面 | `bc.ylo.type = symmetry`、`bc.zlo.type = symmetry` | 管軸は 2 面の交線。角での同時反射も処理される |
| y, z の上端 | specular | 槽の外(固体中)で粒子は届かない |

inflow は「入口面の外に静止した槽がある」境界で、論文の GSIS の圧力入口(付録 A.2: 面の圧力を p_in にする)とは定式が違う。面の近くの圧力は流れの分だけ p_in より少し下がる。試運転では入口面に接する 2 層のセルで p/p_in = 0.9991 ± 0.0008(見積り 1 − sqrt(π)·u/c_m ≈ 0.9985 と同程度)で、Ṁ への影響は約 0.1%。δ=10 では見積りで約 0.3%。解析スクリプトはこの値と補正の目安を出力する。

### 2.3 ガス
| 項目 | 論文 | コード内蔵の He | 使う値 |
|---|---|---|---|
| 分子質量 | 6.65e−27 kg | 6.65e−27 kg | 同じ |
| ω | 0.66 | 0.66 | 同じ |
| T_ref | 273.15 K | 273 K | 273.15 K |
| d_ref | (μ0 = 1.916e−5 Pa·s から) | 2.33e−10 m(VHS) | **2.3002e−10 m** |
| μ(273.15 K) | 1.916e−5 Pa·s | 1.8675e−5 Pa·s(2.6% 小さい) | 1.916e−5 Pa·s |

d_ref は Bird (1994) 式 (4.62) μ_ref = 15 sqrt(m k T_ref/π) / (2(5−2ω)(7−2ω) d_ref²) から求めた。内蔵値のまま計算すると実効的な δ が 2.6% 大きくなり、Ṁ が約 0.5%(δ=1)〜0.9%(δ=10)ずれる(d ln Ṁ / d ln δ ≈ 0.2〜0.33 として見積もり)。入力で `species.He.d_ref`・`T_ref` を上書きする。gmsh を使わず形状を直接作ったのは、鏡映対称性と多角柱の体積を厳密に保つため。

p_in = δ μ0 sqrt(2 R_g T0)/R、sqrt(2 R_g T0) = 1064.99 m/s。結果は無次元で評価するので R の実寸は任意(座標の丸めの点から mm 程度が扱いやすい)。

### 2.5 質量流量と中心線の取り出し(§7 に手順)
- セルの x 方向の質量流束の体積積分 ρ u φ ΔV は Fnum Σ(m v_x)/N_s に等しく、体積率 φ の近似誤差を含まない。x 方向の断面(スラブ)ごとに ṁ(x) = 4 Σ ρ u φ ΔV / Δx(1/4 領域)とすると、定常なら ṁ(x) は x によらない。管のスラブ(0 < x < 10R)の平均を主な値とし、上流槽・下流槽のスラブの平均と、管の前半・後半の差も確認に使う
- コードには境界面の通過粒子数のカウンタがない(流入の生成数はあるが、吸収数は入口と出口を区別できない)。上の方法はこれを補う
- 中心線は各スラブで軸からの距離 r < max(0.35R, 2.2Δy) の完全気体セルに a + b r² を当てはめ、a を値とする。軸に接するセルの値も併記する
- 定常判定と誤差: `sample_reset = 1` で 20 t_ref ごとのブロック平均を書き、平均の開始ステップ以降のブロック間のばらつきから標準誤差を求める(隣り合う 2 ブロックをまとめた値とも比べ、大きい方を採る)。平均窓の前半と後半の差の z 値(|z| < 2 が目安)、ṁ(x) の平坦さ、粒子数の推移も確認する

### 2.6 切断セルの問題と回避
初回の試運転は最初のステップのサンプリングで `DepositMoments: unresolved cut cell contains particles` により停止した。y-z 断面で調べると(`tools/check_cut_cells.py`)、R/Δx が整数なので、等面積多角形の頂点(θ = 0°, 90° で r = 1.0002R)や、円が格子点を通る所(例: (0.6R, 0.8R))で、16×16 の中点に掛からない面積率 1e−6〜5e−3 の流体部分ができていた(Δx = R/4 で 6 セル、R/10 で 16 セル)。粒子がそこに入るとコードは停止する。

回避策として、`make_inputs.py` が y・z 方向のセル幅を Δx の近くで走査し、未解像セルが 0 で、多角形の半径を ±1e−6・±1e−5 だけ変えても 0 のままの値を選ぶ(Δx = R/4 → 0.250875R、R/8 → 0.1254375R、R/10 → 0.1005R)。x 方向の Δx はそのまま(x = 0, 10R の壁をセル境界に合わせるため)。この対策の後、試運転は最後まで止まらなかった。**格子や STL を変えたら、make_inputs.py で入力を作り直す**(自動で再判定される)。

### 2.7 流入処理の性能と max_grid_size
流入粒子は「入口面のセル 1 個を 1 スレッドが受け持ち、その中の粒子を順に作る」実装で、粒子ごとに BVH の内外判定を 3 回行う。スレッドが少ないカーネルを入口面のボックスの数だけ順に呼ぶので、待ち時間が支配的になる。

| 測定(各 300 ステップ、δ=1、Δx = R/4、26 万粒子) | 流入処理 [ms/ステップ] |
|---|---|
| 基準(max_grid_size 32、入口面に 4 ボックス) | 26.8 |
| 流入の数密度 1/10 | 4.2 |
| max_grid_size 64(入口面に 1 ボックス) | 9.6 |

| 測定(各 40 ステップ、δ=10 本計算の設定、1,268 万粒子) | 全体 [s/ステップ] | 移動 | 流入 | 衝突 |
|---|---|---|---|---|
| max_grid_size 32(63 ボックス) | 0.59 | 0.288 | 0.163 | 0.128 |
| max_grid_size 64(16 ボックス) | 0.45 | 0.276 | 0.080 | 0.084 |
| max_grid_size 128(2 ボックス) | **0.35** | 0.261 | 0.023 | 0.060 |

本計算は 128 にした。1 回のカーネルは移動で 0.1〜0.2 s 程度と見積もられ、Windows の TDR(2 秒)には余裕がある。GPU メモリは δ=10 で最大 4.0 GB(AMReX のプール。nvidia-smi では計算前より 4.2 GB 増)。初期化は 6〜10 秒(固体セルにも候補粒子を作ってから除くので、初期化時のメモリは定常時の約 3 倍)。

## 3. 足りない機能と回避策

| 不足 | 影響 | 回避策・提案 |
|---|---|---|
| 2 次元軸対称の計算がない | 3 次元で解く必要がある | 対称面 2 枚で 1/4 領域にする(論文の DSMC は SPARTA の 2 次元軸対称) |
| AMR・可変の粒子重み・局所時間刻みがない | 体積の 87% を占める上流槽(静止に近い)に粒子と時間の大半を使う。下流槽は粒子が少なく(試運転で 0.07 粒子/セル)、中心線の値がばらつく | δ ≤ 10 に限る。Fig.3 の比較範囲(X = 0〜10)は管内なので影響は小さい |
| 境界面の通過量(面ごとの吸収数)の出力がない | Ṁ を直接は得られない | セルの運動量の体積積分から求める(§2.5)。体積率の誤差を含まない |
| 線上・点の出力(プローブ)がない | 中心線は後処理 | plotfile から軸近傍のセルに当てはめ(§2.5) |
| 定常判定の機能がない | — | ブロック平均の後処理(§2.5) |
| 圧力を与える亜音速の入口条件がない | 入口面の圧力が p_in より少し低い(δ=1 で約 0.1%) | 入口面の圧力を出力し、補正の目安を併記(§2.2) |
| 体積率が 0 と判定されたセルに粒子が入ると停止する | 円筒と格子の位置関係で起きる | y・z のセル幅を選んで回避(§2.6)。コード側で最小体積率を与えるなどの対応があると扱いやすい |
| 流入粒子の生成がセル単位の逐次処理 | 小さいボックスでは流入処理が律速 | max_grid_size = 128(§2.7)。粒子単位の並列化がコード側の改善候補 |
| max_grid_size が軸ごとに指定できない | — | 等方の 128 で足りた |
| 初期化で固体セルにも粒子を作る | 初期化時のメモリが定常時の約 3 倍 | δ=10 の全領域が載らない理由の一つ(§4) |
| 倍精度のみ | コンシューマ GPU の FP64 性能が律速になり得る | 実測で 1 粒子・1 ステップ約 28 ns(仮想サブセル込み) |

## 4. 計算量の見積り

基準: δ=10 の測定(1,268 万粒子、max_grid_size 128、GPU 専有)で 0.35 s/ステップ = 27.6 ns/(粒子・ステップ)。サブセルなしは衝突が軽いので 23.7 ns とした。「実測」は短い試験(δ=10 は 40 ステップ、δ=1 は初期化の確認の 5 ステップ)の値。δ=1 の全領域は入口面が 4 倍で流入処理が 0.13 s/ステップかかり、モデル(0.37)より遅かった。粒子数は入口状態の密度で全域を満たした値(定常では管と下流槽が抜けて約 1 割減る)。メモリは「1.2 ×(72 B × 初期化時の候補粒子数 + 240 B × セル数)」で、δ=10 の実測 4.0 GB と合う。ステップ数は過渡(δ=1: 100、δ=10: 150、δ=100: 200 t_ref)と平均(δ=1: 300、δ=10: 210、δ=100: 200 t_ref)の合計。

- MCS/λ は最近接選択で 0.554(V_cell/ppc)^(1/3)/λ、セル内ランダムで 0.6Δx/λ の目安(試運転の実測: 上流槽 0.21、管内 0.11)。DSMC 側 README の目安は 0.2 程度以下。δ=10 の本計算は入口状態で 0.23 とわずかに超えるが、そこは静止に近い上流槽で、勾配のある管内は密度が低いので MCS/λ ∝ n^(2/3) で 0.15〜0.2 に下がる。最近接選択でも MCS/λ = 0.25 を保つには λ³ あたり約 11 粒子が要り、粒子数は 1/λ³ ∝ δ³ で増える。δ=100 では 1/4 領域でも約 1e10 粒子になる
- 論文の DSMC(SPARTA、2 次元軸対称、0.225 / 0.899 / 4.2 M セル、平均 44 粒子/セル、640 コアで 0.55 / 2.19 / 10.2 h = 352 / 1,402 / 6,528 コア時間)は、軸対称と半径方向の重み付けで上流槽の費用を抑えている。3 次元・一様重みのこのコードでは δ=100 は桁違いに重い
- 時間は GPU を専有した場合。他のエージェントが GPU を使うと遅くなる

δ=10 の過渡は、管内の圧力分布が拡散的に緩和する時間(e 倍の時定数 L²/(π²D) ≈ 16 t_ref、D ≈ p R²/8μ)から 150 t_ref 程度と見積もった。定常判定で足りなければチェックポイントから延長する(§7)。

### 5.2 比較の仕方
- Ṁ: 本計算の値(標準誤差つき)を、論文 Table 1(DSMC 0.197 / 0.330、GSIS-PBC 0.198 / 0.326)と、このプロジェクトの GSIS-PBC の結果に並べる。感度計算の差を DSMC 側の数値誤差の目安として併記する
- 中心線: Fig.3 のデジタイズ値(`reference/paper_2610.07658/fig3_{pressure,velocity}_{gsis,cis,dsmc}_delta<δ>.csv`、列 X,P / X,Ux)と、このプロジェクトの GSIS-PBC の中心線に重ねる。論文の DSMC の中心線は δ=100 だけなので、δ=1, 10 では論文の GSIS-PBC の線と CIS の記号が比較相手になる(この DSMC は論文の GSIS-PBC の中心線の独立な確認にもなる)。`analyze_tube.py` が δ に応じて自動で読み、DSMC の中心線を参照の X に線形補間して差を出す。外挿はせず、管内の DSMC のスラブ中心の範囲(例: Δx = R/8 なら X = 0.0625〜9.9375)に入る参照点だけを使う。線は X < 0.15 付近が欠けている系列がある。読み取り誤差は P・Ux で ±0.001 程度(傾きの急な所は ±0.004)
- Ṁ の論文値は `reference/paper_2610.07658/table1_tube.csv` から読む(無ければ make_inputs.py に転記した値)
- 入口条件の違い(§2.2)による差の目安(δ=1 で約 0.1%、δ=10 で約 0.3%)も併記する

## 8. リスク

| リスク | 内容 | 対策 |
|---|---|---|
| 開発途中のコード | 希薄領域の管内流れの定量検証は今回が初めて | δ=1 で論文の DSMC 値と比べてから δ=10 に進む。感度計算で数値誤差の大きさを示す |
| 切断セルでの停止 | 格子・STL を変えると再発し得る | make_inputs.py が y・z のセル幅を自動で選ぶ。STL を変えたら check_cut_cells.py の前提(正 128 角形・等面積)も合わせる |
| 定常に達していない | δ=10 の過渡時間は見積り | ブロックの Ṁ・ṁ(x) の平坦さ・z 値で判定し、必要ならチェックポイントから延長 |
| 統計誤差 | 下流槽・管の出口付近は粒子が少ない | 中心線は当てはめと複数ブロック。Fig.3 の範囲(管内)は十分な粒子数 |
| 入口条件の定式の違い | DSMC は槽の境界、GSIS は圧力入口 | 入口面の圧力を出力し、補正の目安を併記 |
| GPU の共用・TDR | 他の計算と同時に動かすと遅くなる。カーネルが 2 秒を超えると画面のドライバがリセットされる | 本計算は GPU が空いているときに実行。max_grid_size 128 で 1 カーネル 0.1〜0.2 s。問題が出たら 64 に下げる(0.45 s/ステップ) |
| 論文の DSMC との差 | 論文側の DSMC の設定(粒子重み・格子)は不明 | 差は数値と範囲で報告し、合わせ込まない |
| DSMC 側の更新 | build-windows-* は再ビルドされ得る | 既定は dist の固定版。実行ファイルの SHA-256 を run_*.json に記録 |
