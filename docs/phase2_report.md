### `gsis-solver cis-run`

```
gsis-solver cis-run <case.toml> [--out <dir>] [--max-iter N] [--min-iter N] [--tol X]
                    [--backend cpu|cuda] [--precision fp32|fp64] [--set key=value]...
                    [--print-every N] [--vtu-every N] [--no-vtu] [--cells-csv] [--init-from <cells.csv>]
```

- 収束判定は式 (59) の ε < tol(既定は `[gsis].tolerance`)。上限は `--max-iter`(既定 `[kinetic].max_iterations`)
- 出力先の既定は `runs/kinetic/<ケース名>/`(現在のディレクトリから): `history.csv`(反復、ε と成分、残差、全質量、パッチごとの質量流量 kg/s・無次元、熱流束と応力の体積平均、時間の内訳)、`summary.json`(反復数、収束、時間、カーネル別の 1 反復の時間、メモリ、パッチごとの流量と境界面の平均、管なら無次元質量流量 Ṁ)、`fields.vtu`(SI: rho, u, T, p, sigma, q, Ma, Kn_local)、`boundary.vtu`(SI: 質量流束、運動量流束、法線応力、せん断応力、エネルギー流束、境界面の分布の rho, u, T)、`cells.csv`(`--cells-csv`、無次元のセル値)
- `--set key=value` で `[kinetic]` を上書きする(パラメータの比較用)
- `--init-from <cells.csv>` で前回の `cells.csv`(無次元のセル値)から f = f^eq(ρ, u, T) で始める(マクロ量からの再開、spec §4.6)。指定しなければ `[kinetic]` の `initial_pressure`・`initial_temperature` の一様な静止状態
- `fields.vtu` と `cells.csv` にはセルごとの残差(直前の反復の √(ϖ Σ_k R²)/V)も書く(不安定な場所を探す診断用)
- 収束しなくても終了コードは 0(`summary.json` の `converged` と警告で分かる)

## 2. 検証: 平板の熱伝導・クエット流(CIS 単独、`cases/verification/kinetic/`)

### 2.1 条件
- 参照解 `verification/ref1d`(Shakhov、ω = 0.66、Pr = 2/3)と同じ定義: 平均密度・平均壁温の基準状態で Kn(式 (8))、全質量を保つ閉じた領域。4 種類(`heat_lin`: T_L/T0 = 0.95・T_R/T0 = 1.05、`heat_nl`: 0.5・1.5、`couette_lin`: 壁速度 ∓0.1√(RT0)、`couette_nl`: ∓1√(RT0))× Kn = 0.01, 0.1, 1, 10
- メッシュ: 平板(L = 1 mm、y・z は 1 セル厚)の一様な 50・100・200 セル(100 は `cases/slab/mesh/slab_nx100.pmesh`、50・200 は `gsis-tools mesh slab` で作り `cases/verification/kinetic/mesh/` に置いた)
- 側面: 熱伝導は sym_y・sym_z とも対称面、クエット流は sym_y を並進周期・sym_z を対称面(既定。表 2.2)。格子細分化(表 2.3)は側面をすべて並進周期にした版(`_per`)で比べた(対称面の鏡映の遅れ評価で収束が遅く、反復の打ち切りの誤差が細分化の差に混ざるため。収束した解は同じ: heat_lin Kn = 10 の q_x は対称面で −0.0774176、並進周期で −0.0774165)
- 速度格子は管と同じ 30×24×24、[−10, 10]×[−8, 8]²。P = 1、Δt = ∞、リミッタは既定(relative・K = 3)、FP32、GPU
- 収束: ε < 10⁻⁶(表 2.2、u の分母の下限 0.1。2.3 は ε < 2×10⁻⁷、下限 1。熱伝導では u が FP32 の雑音だけなので、下限 0.01 だと ε_u が 10⁻⁶ より下がらない)。対称面のある表 2.2 は反復の打ち切りの誤差を含む(§2.2 の注)

### 3.1 安定性(δ = 1、Δt = ∞、120 反復まで)

最初の既定(全体 RCM の連続区間で P = 64、リミッタ absolute・K = 5)では反復 25 回目に出口付近(x/R = 21.75、r/R = 0.33)のセルで T < 0 になって止まった。設定を変えて比べた結果(当時の実装。出力は整理のため削除した。`cis-run` の `--set cell_ordering=… sweep_blocks=… limiter_eps=… limiter_k=… pseudo_time=… pseudo_cfl=… interface_damping=0` で再現できる):

| RCB・P = 64 | relative・K = 0.3 | ∞ | 安定(100 回で 4.4×10⁻⁴) | 0.61 s |
| RCB・P = 64 | absolute・K = 5 | velocity・CFL 10 | 安定(5.6×10⁻⁴、進みが遅い) | 0.56 s |
| RCB・P = 64 | absolute・K = 5 | velocity・CFL 3 | 安定(1.1×10⁻³、遅い) | 0.56 s |

- 発散したのはどちらも真空に近い膨張域(下流槽の出口付近、管出口の角)。六面体の O 型格子は管の半径方向に細かく軸方向に粗い(縦横比が大きい)ので、2 次の再構成の行き過ぎが起きやすい
- 全体 RCM の連続区間のブロックは、大きな槽で RCM の 1〜3 段の薄い層になる(点ヤコビに近い)。RCB にすると同じ P = 64 でブロックの厚さが 10 セル程度になる
- いったん既定を「RCB・relative・K = 1・Δt = ∞」にした(速く、安定)。擬似時間でも安定化できるが、収束が遅い
- ただし、この設定でも 100 回目以降に残差がゆっくり増えた(1 反復あたり約 1.2%。250 回で 5×10⁻³)。セルごとの残差(`cells.csv` の `residual`)を見ると、管の中の 2 つの面 x/R = 11.907 と 13.364 に集中していた。これは RCB の分割面(ブロック境界)で、軸方向の速い流れがブロック境界を横切るところ。ブロック境界の結合を陽的に(前の反復の値で)扱うことと 2 次の残差の組み合わせによる不安定(点ヤコビの場合と同じ仕組み)と考えられる。対策として、ブロック外の隣接セルとの結合の大きさ β Σ|a⁻| を対角に足すオプション(`interface_damping` = β)を入れた(収束した解は変わらない)。β = 1・0.5 で残差は単調に減り、0.5 の方が速い(250 回で残差 2.4×10⁻⁴)ので既定を 0.5 にした
- 対角補償(β = 0.5)を入れた状態で、弱いリミッタ(relative・K = 3、absolute・K = 5)も 250 回まで安定だった(残差の履歴は K = 1 とほぼ同じ)。最初の absolute・K = 5 の発散も、ブロック境界の不安定が引き金だったと考えられる。そこで既定のリミッタを relative・K = 3 にした(§6)

読み取れること:
- **ε < 10⁻⁵ で止めた値:** δ = 10 では入口と出口の流量が 30% 近く違い(0.234 / 0.316)、定常から遠い(上流槽の遅いモード、§3.4)。設定どうしは反復数と出口の流量で比べる。δ = 1 は入口・出口が ±0.7%(β = 0 で 3,000 回まで回した例では入口・出口とも 0.1964 で、これがこのメッシュの定常値)
- **空間ブロック数 P:** P を増やすと反復が増える(δ = 1 で P = 1 → 256 が 292 → 649 回、δ = 10 で 628 → 777 回)。1 反復の時間は P とともに減るが頭打ち(このメッシュでは P = 7 以上でほぼ一定)。全体の管(135,104 セル)で P = 64 → 128 にすると 1 反復は 8% 速くなる(§3.2)が、1 ブロックのセル数が半分になり(粗い管の P = 7 → 16 に相当)反復が 3〜20% 増えるので、既定(セル数/2048、上限 64)のままにした
- **ブロックの形:** 全体 RCM の連続区間は、P = 7 なら RCB と同程度だが、P = 64 では δ = 1 で発散し(反復 480 回目に T < 0)、δ = 10 も反復が 1.4 倍。RCB のコンパクトなブロックが必要
- **速度チャンク:** 結果はビット単位で同じ(反復数・流量が一致)。小さいメッシュでチャンクを小さくするとスイープの並列度(P × チャンク)が足りず遅くなる(512 点で 6.5 倍)。既定(空き VRAM から自動。このメッシュでは全点)がよい
- **擬似時間:** Δt = ∞ が最も速い。velocity・CFL 10 で反復 1.05〜1.25 倍、CFL 3 で 1.2〜1.8 倍、CFL 1 で 1.5〜3.2 倍。global は CFL 100 で 1.15〜1.9 倍。擬似時間を入れると 1 反復の変化が小さくなるので、同じ ε でも定常解から遠いところで止まる(δ = 1 の global・CFL 30 と velocity・CFL 1 で入口と出口が 5% 違う)
- **リミッタ:** 反復数は変わらない。K ≥ 3 とリミッタなしの差は 0.1〜0.2%。K = 0.3(強く効かせる)では δ = 10 の出口の流量が 4% 小さい(0.302 ↔ 0.316)。細かい管の δ = 1 では K = 1 と 3 の差は 0.04%(§3.3)
- **ブロック境界の対角補償 β:** δ = 1 では β = 0 だと 3,000 回で ε が 10⁻³ から下がらない(残差が O(1) のまま。流量は定常に達しているので、ブロック境界の局所的な不安定)。β = 0.25〜1 で 331〜364 回。δ = 10 では β によらず 644〜662 回
- **壁の ρ_Γ の緩和:** 0.5 にすると反復が増える(δ = 1 で 342 → 406 回)。既定は緩和なし

## 5. フェーズ 4(GSIS の結合)への引き継ぎ

`KineticSolver`(`src/kinetic/kinetic_solver.hpp`)の使い方。入出力はすべて無次元量(spec §3.2、R = 1、p = ρT)、セル・境界面は元のメッシュの番号、型は `src/gsis/interfaces.hpp`。

```cpp
KineticSolver kin(config, mesh, geometry, parse_kinetic_params(config));
kin.initialize_equilibrium(W0);                 // NSF の PBC で作った初期場(仮定 A9)
for (int n = 0; ; ++n) {
  for (int l = 0; l < config.gsis.n_cis; ++l) kin.sweep();   // f^n → f^{n+1/2}(sweep は必要なら prepare する)
  const KineticMoments m = kin.moments();                    // W^{n+1/2}, σ, q(FP64)
  const BoundaryKineticFluxes fb = kin.boundary_fluxes();    // F^{±,0}_b(面積を掛けた値)と境界面の [ρ, u, T]
  CellMacroState w_new = /* PBC(m, fb, HoT) */;
  const long long replaced = kin.apply_gsis_correction(m.state, w_new);  // 式 (14) と負値の置換
  // 収束判定 (59) は GSIS の反復どうし(W^{n+1} と W^n)で行う
}
```

- `moments()` と `boundary_fluxes()` は、f が変わっていなければ前回の `prepare()` の結果を返す(同じ f について何度呼んでもよい)。`boundary_fluxes()` の拡散壁の F⁻ は緩和しない ρ_Γ で作るので F⁺_ρ + F⁻_ρ = 0(壁の正味質量流束 0)。対称面の F⁻ は鏡映した再構成値の和、並進周期の面は F⁻ = 0・F⁺ = セル値の流束(PBC は並進周期の面を和から除く前提)
- `apply_gsis_correction` は W の ρ, u, T だけを使う(p は見ない)。閾値は −10⁻⁸ ρ_new/T_new^{3/2}。補正の後は `iteration()` は進まないが f は変わったものとして扱う(次の `prepare()` で境界条件を作り直す)
- 1 回の `sweep()`(勾配・残差・前進・後退)は管で 0.57 s、`moments()` + `boundary_fluxes()`(= `prepare()`)は 0.04 s 程度(モーメント 18 ms、境界 23 ms、転送)
- 閉じた領域では `prepare()` が反復ごとに全質量を初期化直後の値に規格化する。GSIS で閉じた領域を解くときも同じ(PBC 側の全質量の合わせ方と揃える必要がある)
- 拡散壁の ρ_Γ・圧力境界の W_b は、補正の後の最初の `prepare()` で新しい f から作り直す(遅れ評価)

## 6. 決めたこと

| 項目 | 決めたこと | 理由 |
|---|---|---|
| CIS の解法(A1) | 1 次風上の陰的演算子 + 2 次の残差(defect correction)、LU-SGS 1 往復 / 反復、空間ブロック間はブロック・ヤコビ | 設計どおり |
| 擬似時間刻み(A2) | 既定は Δt = ∞。`pseudo_time = "global"`(Δt_i = CFL V_i/(ξ_max Σ|S|))と `"velocity"`(V/Δt = Σa⁺/CFL)を選べる | 平板・管で Δt = ∞ が安定・最速(下の 2 項の条件で)。pseudo-time は安定化するが収束が遅い(§4) |
| LU-SGS のブロック | RCB(座標の再帰二分割)のコンパクトなブロック、中は逆 Cuthill–McKee。P は既定で セル数/2048 を 1〜64 に。ブロック境界の結合の対角補償 β = 0.5(`interface_damping`) | 全体 RCM の連続区間では大きな領域でブロックが薄い層になり、管で発散した。1 セルのブロック(点ヤコビ)は 2 次の残差と組み合わせると不安定(Fourier 解析・平板で確認)。RCB でも管を横切る分割面で残差がゆっくり増えたので対角補償を入れた |
| リミッタ(A4) | Venkatakrishnan、ε² = (Kh)³ · max(|f_max|, |f_min|)²(relative)、K = 3 | absolute・K = 5 では f(≤ 0.06)に対して ε が大きすぎてリミッタがどこでも働かない。最初は管(対角補償なし)の発散を抑えるため K = 1 にしたが、対角補償を入れると K = 3・absolute K = 5 でも安定だった。K = 1 は粗い管の出口の流量をリミッタなしから 0.4〜2% 動かす(K = 3 は 0.15% 以内、§4 と `param_study_relK1.csv`)ので、強い不連続(真空との境)でだけ働く K = 3 にした。滑らかな平板では K = 1 と 3 の差は小さく、absolute・K = 5 より流束の差が 10⁻⁵ → 10⁻⁴ 程度に増える(合格の目安の 1/10 以下、§2) |
| f の勾配の境界値(A3) | 流入側は流入分布、流出側はセル値。対称面は (f(ξ) + f(ξ'))/2 | 対称面で鏡映点のセル値をそのまま面中心に置くと、反対称成分が 2 倍に増幅されて 1 セル厚の平板で発散した |
| 速度点の保存順 | 対称面の軸の鏡映の組(軌道)を連続に並べる | 鏡映点が常に同じチャンク・同じタイルに入る(対称面の流入値に鏡映点の制限付き勾配を使える) |
| モーメントの集計 | FP32 の f を前回の u のまわりのシフト付きの和にして、スレッドごとに Kahan の補正付き FP32、ブロック内は FP64 | GeForce の FP64 は FP32 の 1/64 で、FP64 で全部足すと 1 反復 80 ms 以上かかる見込み。シフトで桁落ちを避ける |
| 壁の流入密度 | 遅れ評価(反復の初めの f の再構成値から)、`wall_relaxation` で緩和できる(既定 1) | 設計どおり。F⁻ は緩和しない値(壁の正味質量流束 0) |
| 閉じた領域 | 反復ごとに全質量を初期化直後の値に規格化 | spec §3.8 |
| 管の初期状態(CIS 単独) | 全域で入口の状態(p_in, T0)に静止した平衡分布(`initial_pressure = 1`、`initial_temperature = 1`) | 論文に書かれていない。GSIS では NSF の PBC の解から始める(A9) |
| 収束判定 | 式 (59)。u の分母に下限 0.01 √(RT0)(`convergence_u_floor`) | u ≈ 0 の流れで FP32 の雑音だけの ε_u が下がらない |
| VRAM の余裕 | 速度チャンクの自動決定で 1 GB を残す | WDDM の空き容量の報告が当てにならず、600 MB では空きがほぼ 0 と報告された |

## 7. 未解決の点

- **CIS 単独の収束判定:** 式 (59) の ε は 1 反復の変化なので、CIS の収束が遅いと定常の手前で止まる。管 δ = 1 の ε < 10⁻⁵ では入口と出口の流量が 4.7% 違う。δ = 10 は上流槽の遅い振動(§3.4)のため ε < 10⁻⁶ でも 4% 違った。CIS 単独の結果を使うときは入口・出口の流量の一致も確かめる。GSIS では反復が少なく、問題にならない見込み
- **δ ≥ 10 の CIS の精度:** δ = 10 の CIS の収束解の Ṁ は DSMC より 2〜3% 大きい(§3.4)。中心線は論文の CIS とよく一致するので、論文のいう CIS の数値散逸(槽のセルが平均自由行程より大きい)と考える。CIS 単独では直せない(GSIS の漸近保存性で直る見込み。フェーズ 4 で確かめる)
- **対称面の収束の遅さ:** 鏡映した速度点の流入を前の反復の値で固定しているため、面にほぼ平行な速度点で大きな擬似時間刻みと同じ働きになる。1 セル厚の平板では 100 倍近く遅い(Kn = 10 の熱伝導で 2,206 反復 ↔ 並進周期で 20 反復)。軌道(鏡映の組、最大 8 点)ごとの小さな連立 1 次方程式を warp 内で解けば陰的にできる(未実装)。1/4 領域の 3 次元計算では対称面に接する層だけの問題なので影響は小さいはず(未確認)
- **自由分子極限の管(設計書 §13):** 未実施。圧力入口(付録 A.2)は Δu の分だけ流れのある Maxwell 分布を出すので、Clausing の透過確率(静止した槽)とは厳密に比べられない。静止した槽の境界(遠方場、spec では v1 の範囲外)が要る
- **性能:** カーネルの実効帯域は 180〜350 GB/s(ピークの 20〜40%)。LU-SGS のスイープはセルを順に処理する待ち時間で律速。目標(2 s/反復)は満たしているので最適化はしていない
- **四面体メッシュでの安定性:** 既定(relative・K = 3)では四面体の管が下流槽の真空に近いセルで発散する(§3.5)。K = 2・1 なら安定だが ε がそれぞれ 7×10⁻⁵・1.2×10⁻⁴ で頭打ちになる(流量は収束)。面の再構成値が負にならないように φ を制限する正値性のリミッタ(`limited_gradient` に面ごとに φ ≤ f_i / (−∇f·r_f) を足すだけで、CPU・GPU 共通)を入れれば K = 3 のまま安定にできる見込み(未実装。入れると六面体の結果も少し変わりうるので、検証のやり直しが要る)
- **Δt = ∞ の安定性:** RCB のブロック・relative のリミッタ・ブロック境界の対角補償で、六面体の管の δ = 1・10 は安定。δ = 100・1000 は未確認(CIS 単独では収束に数千反復以上かかる見込み(論文の CIS は 2,796 回・7,847 回)なので、フェーズ 4 の GSIS で確かめる)
